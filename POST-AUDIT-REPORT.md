## B. Remaining security risks and limits

1. **Critical if quarantine is removed:** no production provider/pool profile has passed a new independent security review. Real paid build transactions and market output are unavailable. ALT resolution, unsupported route/CPI expansion and swap success asset-effects reconciliation remain unsupported and fail closed. The new adapter/ledger are internal offline components, not a deployed live treasury workflow. Payout reconciliation supports strictly decoded USDC effects; unsupported/absent evidence holds allocations. Existing web guards/shared broadcaster remain unconditional.
2. **Live proof unavailable:** no owner public payer address or balance was supplied; the owner elected to handle that preflight personally. The public 402 uses a placeholder address. It is not an owner-specific approval plan or successful payment. The tiny 0.001 SOL quote parameter is not a trade; provider minimums, liquidity and real paid response shape remain unproven. A payment may settle while the API returns no usable quote; that outcome is preserved as a payment, not a successful quote.
3. **Trusted local account/filesystem:** Windows ACLs, a reviewed plan hash and the same durable journal directory are required. POSIX mode bits do not enforce Windows privacy. A malicious process running as the owner can read environment/key files or rewrite/delete a journal and recompute its hash chain. Changing directories/resetting history defeats accounting and is outside the safety model. Lock recovery assumes no racing local operator and refuses live/reused PIDs.
4. **Trusted RPC and external activity:** independent RPC/explorer checks are advised. Genesis/status/account data can be falsified by a malicious RPC. Dedicated wallet operation is assumed; an external concurrent withdrawal can defeat any client-side reserve precheck. RPC latency, malformed evidence or absent finalized status can leave conservative holds requiring manual investigation. No automatic negative reconciliation, re-signing, budget refund or retry is provided.
5. **Production untested:** PostgreSQL multi-instance deployment, actual browser wallet extensions, hosted proxy/HTTPS behavior, live signer permissions and a funded signer have not been exercised. Tests use PGlite and local deterministic RPC/HTTP fixtures. Live organization provisioning still requires review. A new independent review is mandatory before exposing financial execution.
6. The local raw API response/hash records a trusted-client capture; Solana proves the payment, not the truth of a market-price response. Public artifacts intentionally reveal public addresses/unsigned message bytes; the owner must review sharing. Private payment authorization headers, raw provider payloads, tokens and key material are excluded.
7. Historical unrelated audit limitations, including bearer proof-link revocation UI and an absent autonomous payroll worker, are unchanged. No autonomous trading/payroll service is claimed. The standalone CLI signer is not controlled by the demo pause switch.
