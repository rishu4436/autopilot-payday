# AUTOPILOT PAYDAY independent engineering audit

Date: 2026-11-10 (Asia/Kolkata). Scope: actual files under `D:\payday`, dependency tree, original and expanded tests, isolated production browser runs, official Hermes references and unpaid endpoints. No financial signature, payment, swap or payout was executed. The owner chose to perform wallet setup and preflight personally.

## Verdict

**CONDITIONAL PASS for a clearly labeled simulated payroll / live-unpaid demonstration. FAIL for live financial execution or production readiness.** Critical/high execution risks are fixed or made unreachable by code-level quarantine. Provider-specific swap authorization, durable live payout submission/reconciliation and production organization provisioning remain absent. Passing deterministic tests does not validate a real paid integration. The local one-plan paid-quote experiment is prepared for a separately approved owner-operated test; it has not been executed with funds.

There is no `.git` directory, ancestor repository or configured remote in the supplied workspace. No branch, commit or push was created, and no commit IDs are claimed. `audit/baseline.zip` preserves the original audited source subset; `audit/changed-files.json` records exact changed/new/deleted paths and SHA-256 hashes relative to that baseline. Use the actual upstream checkout before committing or pushing.

## Hermes compatibility findings

Primary references retrieved during the audit: [live agent guide](https://hermes.swap.io/llms.txt), [live discovery](https://hermes.swap.io/v1/info), [official MCP repository](https://github.com/swap-dot-io/hermes-mcp), [official quickstart](https://docs.swap.io/developer-tools/agent-api-x402/quickstart). Direct HTTPS reads succeeded where the web reader could not render the endpoint. Raw live discovery and unpaid response, capture timestamp and request are in `audit/hermes-evidence.json`.

* The quote request uses `input.token/amount/chainKey`, `output.token/chainKey`, `userAddress`, and `slippageBps`. Amounts are atomic strings and chain key is `sol`. The reproduced unpaid quote returned HTTP 402, x402 version 1, **3007** atomic USDC (0.003007 USDC). This proves the payment challenge was received; upstream paid quote schema and liquidity are still unverified.
* Discovery lists a **3000** atomic USDC base quote price. The actual request challenge asked for **3007**. The live guide explicitly describes parameter-aware pricing; the request's 402 controls exact approval. Prices are captured observations, not a permanent price promise.
* Observed Solana payee: `BPz2u6eoWLervxEqfpsMCVmKk7h6fEVsd7L5rvEibMfD`; facilitator fee payer: `2wKupLR9q6wXYppw8Gr2NvWxKBUqm4PPJKkQfoxHDBg4`; asset: canonical mainnet USDC. The Base alternative is not approved. Local plans pin full terms; a later changed challenge is rejected.
* `x402-solana` **3.0.1** is the installed client. Its local source supports body-based v1 and `PAYMENT-REQUIRED` header v2, exposes `beforePayment`, and creates the checked gasless transfer locally. The repository normalizes both challenge formats and tests installed-client abort behavior without RPC/signing. This is **compatibility evidence before payment**, not proof of successful settlement.
* The official MCP README and quickstart call status polling free. Live guide/discovery mark `GET /v1/swap/status` paid, with a 3000 atomic base price. Treat it as paid; do not poll it assuming no charge. The quickstart also distinguishes submit acceptance from confirmation/finality. The app uses Solana RPC confirmation instead. Receipt wording in documentation does not replace independent transaction verification.
* Build request must send the chosen raw `providerQuote` as `quoteResponse`, with provider key and `userAddress`; the wrapper is not interchangeable. Synthetic contract tests preserve the object. No live paid build was attempted. Quote response fields/minimum outputs, provider-specific instructions, expiry behavior and actual market output remain unverified.
* `POST /v1/transfer/build-tx` is a paid unsigned batch builder, with `source_wallet`, `token`, `destinations[{wallet,amount}]`, `create_ata`, and `gasless`. The app's existing builder constructs checked USDC transfers locally instead; it is **not** a verified paid Hermes batch-transfer integration. The local builder now rejects allocation IDs repeated across chunks and invalid sizes/mints/decimals/u64 amounts.

## Remaining risks and limits

1. Live swap instruction decoders, resolved lookup-table checks, per-asset spending authorization, immutable approved/signed transaction persistence and crash-safe treasury reconciliation are absent. Routes stay quarantined. Live payout submission/confirmation is also absent. A background agent worker is absent.
2. No dedicated payer address/balance, paid quote, real receipt, live market quote, swap or payout was inspected. Owner chose to do wallet steps personally. No actual chain-backed paid result can be shown in the video yet.
   The funded signer was not started with a key. Its bind/auth policy was reviewed in source and exercised with deterministic policy tests; default signer and paid-quote commands were executed only to verify refusal without opt-in (both exit 1).
3. The local signer relies on a trusted OS account, private file ACLs, reviewed plan hash, one unmodified journal directory and trustworthy RPC. A same-user local process can read keys/tokens or edit the journal. A malicious RPC can lie; use independent RPC/explorer checks for live evidence. Windows ignores POSIX permission bits, so apply actual ACLs per the runbook.
4. Uncertain payment reconciliation is manual and conservatively blocks later payments. No CLI automatically clears uncertain rows. Local journal deletion or use of multiple directories defeats cumulative history; it must never be used as retry recovery.
   The demo app's pause switch does not revoke a separately approved standalone CLI plan. Stop the local signer with Ctrl+C to halt that independent experiment; do not assume an app setting controls an external process.
5. Six moderate dependency advisory entries remain (uuid, stream-json, minimatch; some packages have multiple entries). Major transitive replacement of stream-json/uuid can break their consumers; no unsupported override is silently imposed. See the final machine-readable audit for exact paths. Next's lint step may warn that the optional Next ESLint plugin is absent; the independent TypeScript/hooks ESLint check still runs.
6. External PostgreSQL execution has not been reproduced; real DB tests use PGlite. Production multi-instance operation, hosted HTTPS/cookie/proxy deployment and browser wallet extensions are not validated. The nonce/signature verifier is exercised locally with deterministic keys. No production-readiness claim follows from those tests.
7. Shared contributor proofs expose only that contributor's items, but batch-level totals remain organization metadata for an authorized member. Public proof links are bearer links with seven-day expiry; only owners can publish them. No revocation UI is implemented.
8. The source directory had no Git history, so a Git-history secret scan and push could not be performed. The source/config fixture scan and client-bundle scan are scoped and recorded; they are not guarantees about files outside this workspace or historical credentials.
